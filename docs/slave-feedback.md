# Slave round feedback and admin observation

- Default mode consists of two rounds scored 4/3/2/1 per round; highest total wins, including ties. Each completed game saves immediately before the next transition. Human tables count toward the leaderboard; tables with bots save human history with `ranked:false` and do not change totals, wins or losses. Bots do not get profile records. Debug/abandoned rounds remain excluded. Result IDs still prevent replay after reconnect/restart.
- Placements trigger synthesized sound effects and on-screen text immediately, including the first finisher while the others continue. No spoken narration or speech synthesis is used. Browser audio restrictions still require an initial user gesture; physical speakers and mobile Safari need real-device testing.
- `self.exchangeReceipt` contains only that recipient's sent/received cards and partner. It survives reconnect for the current round, is replaced on the next deal, and never appears on another player's seat or in public logs. The table shows a dismissible transfer animation, labels incoming cards, and retains a receipt below the table. Reduced motion keeps the labels without animation.
- When answering a multi-card pile, tapping a card selects the smallest server-authorized combination containing it, including pairs of 2s. Selection never submits automatically. Tap selected cards to adjust the combination; exchange choices remain individual.
- Site admins can use `/m` in production. Ordinary hosts only have debug rights in staging. The first inspection marks the table as a test, excluding subsequent results from stats. Hands stay in private acknowledgements.
- Site admins can click any room card to open `/admin/observe/:roomId`, including full, locked and active rooms. The admin dashboard room details also link there. Ghost mode shows public room state, players, phase and public action history; Slave additionally shows counts, standings and pile. It provides public chat with an explicit Ghost Admin label. It does not occupy a seat, receive a hand, vote, change the host, mark presence, or count toward statistics. It uses separate sockets so observing another room does not replace a player's socket. `/m` in Ghost mode privately inspects Slave hands and marks the table as a test. Closing the page does not remove a player.
- Both HTTP and socket handlers enforce admin authorization. Regular users cannot use observation or observer chat; revoking site-admin rights ends observation on refresh. Session-authenticated dashboard admins are supported as well.

Validation: `smoke:slave`, `smoke:slave:records`, `smoke:slave:history:e2e`, `smoke:slave:ux`, and `smoke:slave:play`. Browser tests can use an installed Chromium executable when the Playwright browser cache is absent.

Bot play prioritizes finishing the hand, otherwise leads the lowest rank as a complete set. Against an existing pile it chooses the cheapest equal-size winning set before using a triple/quad cut. It uses only its own cards and public pile, and never changes the legal-move ordering used by clients or the existing human timeout fallback.


## Room play mode

The host can choose **♠ 2 รอบ** (default) or **∞ เล่นวน** in the room lobby. Play mode is validated server-side and locked while playing.

Continuous mode has no two-round game boundary or automatic lobby redirect. Each round's actual finishing order becomes king/queen/vice-slave/slave for the next exchange. The game ID remains stable, rounds and action steps increase monotonically, and score sheets never reset positions every two rounds. Each completed round records its own idempotent result and `round_end` activity. Human rounds count toward rankings; rounds with bots retain human history only. Debug exclusion carries forward. Restart preserves the mode, roles and exchange state; older two-round looping snapshots migrate to the endless format without replaying saved results. Only the latest round result is kept in the live snapshot, while the normal player history limit still applies.
